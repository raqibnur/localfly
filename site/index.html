How it works

From localhost to link
in three steps.

No terminal, no config files, no router settings. Localfly dials out to a relay, so nothing on your network changes.

Self-host

Your relay. Your domain. Real HTTPS.

Out of the box Localfly uses the free public relay at bore.pub. For stable, padlocked addresses, run your own on a $5 server.

  • bore and Caddy in one docker compose up
  • Certificates fetched and renewed automatically
  • A secret, so only you can open tunnels
Read the self-hosting guide → 
# on your server
$ git clone https://github.com/raqibnur/localfly
$ cd localfly/deploy && cp .env.example .env
$ nano Caddyfile  # web.yourdomain.com → :40001
$ docker compose up -d
✔ relay  listening on :7835
✔ caddy  certificate for web.yourdomain.com

Is it really free?

Yes. The app is open source under the MIT license and has no paid features. The free relay at bore.pub is run by the bore project.

Why does my bore.pub address change?

bore.pub hands out a random port each time a tunnel opens. For addresses that never change, with HTTPS, run your own relay. The self-hosting guide takes about 15 minutes.

Is it safe?

Nothing is reachable until you switch an app on, and you can switch it off instantly. While it’s on, anyone with the address can open that app, so only share what you mean to share. On bore.pub, traffic is plain http://; use your own relay for HTTPS.

Does it work with Next.js, Vite, Rails, Laravel…?

Anything that listens on a TCP port on your Mac works: web apps, APIs, webhooks, even game servers.

Which Macs are supported?

macOS 13 Ventura or later, on Apple silicon and Intel.
